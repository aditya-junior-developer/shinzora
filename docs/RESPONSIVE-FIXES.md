# Responsive audit — what it found and what changed

The measurements live in `docs/RESPONSIVE-REPORT.md` (regenerated by
`node scripts/responsive-audit.mjs`). This file records the findings and the fixes,
because those do not get regenerated.

Scope: 23 HTML pages, plus the seven dashboard views that live behind one URL,
= 29 targets × 3 widths (1440 px desktop, 834 px tablet, 390 px mobile) =
**87 page/viewport combinations**, all screenshotted into
`docs/media/responsive/` (87 images).

Final state: **87 combinations, 29 targets, 0 issues.**

---

## Findings and fixes

### 1. `/download/` overflowed the mobile viewport by 129 px

**Found:** at 390 px the page scrolled sideways. The offender was
`article.dl-card.is-live`, measured at 495 px inside a 390 px viewport, pushing
`span.dl-status.available` off-screen.

**Cause:** `.dl-grid` was a grid with an implicit `1fr` track. `1fr` means
"at least min-content", and the min-content width of a card containing a
`white-space: pre` command block is the width of the longest command. The grid
could not shrink below it.

**Fix** (`public/download/index.html`):

```css
.dl-grid { grid-template-columns: minmax(0, 1fr); }
@media (min-width: 760px) { .dl-grid { grid-template-columns: repeat(2, minmax(0, 1fr)); } }
.dl-card { min-width: 0; }
.dl-card-top { flex-wrap: wrap; }
pre { max-width: 100%; }
```

`minmax(0, …)` lets the track shrink and leaves the code block scrolling inside
its own box, which is what it already had `overflow-x: auto` for.

**Re-measured:** 0 px overflow at 390 px and at 834 px.

### 2. `/system-check/` took longer than 30 seconds and never settled

**Found:** the audit could not finish the page at any width — `page.goto` timed
out waiting for the network to go quiet.

**Cause:** the diagnostic run probed 25 tables, three RPCs, three storage buckets
and the edge functions **one after another**, each against the live project.
Measured sum of request time: 19 s; with the serialised waits, the page ran past
30 s. The probes are independent, so the queue was pure latency.

**Fix** (`public/js/boot/system-check.js`):

- Added a bounded `mapLimit(items, limit, worker)` helper.
- Schema probes: sequential → 6 in flight.
- RPC probes: sequential → 4 in flight.
- Storage bucket probes moved into their own `checkStorage()` step, 3 in flight.
- The probe order and the wording of every result are unchanged.

**Re-measured:** the diagnostic run completes in **6.4 s**, reporting
"No failures. 6 warnings — usually an unconfigured provider", with 42 requests.

### 3. Audit findings that were not defects

Two findings were the harness being wrong, not the site, and are recorded so the
report is not read as "nothing was found":

- **The `400`s on `/system-check/`** (`onboarding_progress?select=…`,
  `integration_tokens?select=…`) are the legacy-schema probes *asking* whether a
  column exists. A 400 is the answer they need. The audit now tolerates those
  URLs for that page only, and the reason is written in the script.
- **"Small targets" on legal pages** were inline links inside sentences. A link in
  a paragraph is text, not a control; the measurement now only counts buttons,
  fields and links styled or placed as controls.

### 4. Dashboard screenshots were overwriting each other

Seven dashboard views share one URL and differ by `?view=`. The first run wrote
`app-390.jpg` seven times, so six views had no evidence. Screenshot names now
include the view (`app-requests-390.jpg`), and each of the seven has its own
three images.

## What the numbers say, and what they do not

Measured: no horizontal overflow anywhere, no element extending past the
viewport, no console errors on any page, no failed requests outside the intended
404s, and no page that renders empty.

Not measured: visual harmony, contrast ratios, or how a page feels between the
three sampled widths. A page can pass every check above and still be ugly; the
screenshots exist so that judgement can be made by eye rather than taken on faith.

## Header, after a seventh link

Seven links, a wordmark and three actions no longer fit a single row between
960 px and 1200 px, so "AI builder" and "Business OS" wrapped and the bar grew by
a line. The row is now explicitly a single line (`flex-wrap: nowrap`,
`white-space: nowrap`, actions non-shrinking), the three secondary links withdraw
below 1200 px, and the download button becomes an icon below 1100 px. Measured at
thirteen widths from 1600 px to 390 px: every link occupies one line, nothing
overlaps, nothing overflows, and the header is 69 px tall at every desktop width.
Screenshots: `docs/media/fixes/navbar-1440.png`, `navbar-1100.png`.
